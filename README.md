## Profile

Cybersecurity practitioner focused on understanding how applications and systems fail, how suspicious activity can be investigated, and how security findings can lead to practical improvements.

My work and learning span **web application penetration testing, reconnaissance, vulnerability assessment, SOC operations, SIEM-based investigation, and malware analysis**. I value repeatable methodology, useful evidence, clear reporting, and security work performed within an authorized scope.

## 01 / Offensive Security

<sub>RED TEAM · WEB APPLICATION SECURITY · RECONNAISSANCE</sub>

- **Web penetration testing** — assess common web and API weaknesses, authentication and session handling, access control, input validation, and security configuration.
- **OWASP Top 10** — use the risk categories to guide assessment, validation, impact analysis, and remediation advice.
- **Reconnaissance** — map in-scope assets, enumerate subdomains, probe HTTP services, crawl websites, and organize discovered endpoints.
- **Vulnerability assessment** — validate findings, collect reproducible evidence, prioritize risk, and communicate remediation clearly.
- **Reporting & retesting** — document scope, methodology, impact, evidence, limitations, and verify fixes where possible.

**Toolkit**

`Burp Suite` `Subfinder` `Katana` `Nmap` `OWASP ZAP` `ffuf` `SQLmap` `Metasploit`

## 02 / Defensive Security

<sub>BLUE TEAM · SOC · SIEM · THREAT DETECTION</sub>

- **SOC workflows** — monitor security events, triage alerts, gather context, document investigations, and escalate when appropriate.
- **SIEM & log analysis** — search and filter events, correlate activity, build timelines, and investigate suspicious patterns.
- **Threat investigation** — review authentication, endpoint, and network activity; assess indicators; and distinguish suspicious behavior from expected activity.
- **Detection engineering fundamentals** — translate investigation findings into detection ideas, tuning opportunities, and defensive recommendations.
- **Incident response fundamentals** — support structured investigation, evidence preservation, documentation, and follow-up improvements.

**Platforms & concepts**

`Wazuh` `Splunk` `SIEM` `Log Analysis` `IOC Triage` `MITRE ATT&CK` `Incident Response`

## 03 / Malware Analysis

<sub>STATIC ANALYSIS · DYNAMIC ANALYSIS · THREAT RESEARCH</sub>

- **Static inspection** — examine hashes, metadata, strings, imports, and other file artifacts without executing a sample.
- **Behavioral analysis** — study process, file, persistence, and network behavior in an isolated analysis environment.
- **IOC extraction** — document relevant hashes, domains, IPs, paths, and other indicators for investigation.
- **Research notes** — connect observed behavior to known techniques and write concise findings with defensive takeaways.

**Analysis areas**

`File Triage` `Strings & Metadata` `IOC Extraction` `Behavioral Analysis` `YARA Concepts` `Isolated Lab Work`

> Malware research belongs in a controlled, isolated environment. Unknown samples should never be executed on a daily-use machine.

## 07 / Working Principles

- Test only systems I own or am explicitly authorized to assess.
- Prefer evidence and reproducible steps over assumptions.
- Explain impact in terms of risk, not just tool output.
- Treat detection and remediation as part of the security process.
- Keep sensitive client data, credentials, and private findings out of public repositories.
- Keep learning, validate findings, and document limitations honestly.
